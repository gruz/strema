# FORPOST Stream

Трансляція відео з пристрою DZYGA на RTMP сервер з динамічним оверлеєм частоти.

## 🚀 Швидке встановлення

**Одна команда через SSH:**

```bash
curl -fsSL https://raw.githubusercontent.com/gruz/strema/master/install.sh | bash
```

Після встановлення в консолі з'явиться посилання на веб-інтерфейс:
```
🌐 Web Interface: http://192.168.1.X:8081
```

**⚠️ ВАЖЛИВО:** Стрімінг за замовчуванням **ВИМКНЕНИЙ**. Увімкніть його через веб-інтерфейс.

> **Примітка:** За замовчуванням встановлюється останній стабільний реліз.
> Якщо на пристрої стара версія бінарників `dzyga`/`dzyga_web`, інсталятор
> автоматично оновить їх до актуальної (зі збереженням бекапу).

## ⚙️ Веб-інтерфейс

Після встановлення відкрийте у браузері:
```
http://[IP-адреса]:8081
```

**Можливості:**
- 🎬 Керування трансляцією (старт/стоп)
- ⚙️ Налаштування якості відео
- 📝 Оверлей тексту та частоти
- 🔄 Автоматичні оновлення
- 📊 Режими роботи при скануванні
- 🖥️ Керування пристроєм Dzyga (екран, кнопки, частота)
- 🧩 Оновлення компонентів Dzyga (прошивка RP2040, `dzyga`, `dzyga_web`)
- 🌐 Керування VPN (Tailscale / ZeroTier / WireGuard)
- 🚜 `/fleet` — масові оновлення й конфігурація пристроїв у VPN
  (пристрій можна приховати з автопошуку — «Видимість у флоті»
  в розширених налаштуваннях)
- 📺 `/multiview` — відео з усього флоту на одному екрані: перегляд, керування
  стрімом, динамічний оверлей і частота Dzyga для кожного пристрою

### Перегляд у зовнішньому плеєрі

Пристрій роздає відео по RTSP на порті 8554 (посилання — у блоці превʼю
на головній сторінці):

- `rtsp://<адреса>:8554/overlay` — потік з усіма оверлеями (текст, частота);
- `rtsp://<адреса>:8554/raw` — чистий потік камери без оверлею;
- `rtsp://<адреса>:8554/devvideo0` — канонічна адреса для старих клієнтів
  (за замовчуванням теж з оверлеєм; перемикається опцією
  `RTSP_DEVVIDEO0_OVERLAY`).

RTSP — live-протокол: відставання не накопичується, бо запізнілі пакети
відкидаються, а не буферизуються. Для ще меншої затримки:

- **mpv**: `mpv --profile=low-latency rtsp://<адреса>:8554/overlay`
- **VLC**: `vlc --network-caching=300 rtsp://<адреса>:8554/overlay`
  (можна спуститись до `100`, але на поганому каналі буде розсинхрон).
- `/raw` швидший за `/overlay` на ~0.1 с — він минає енкодер зовсім.
- За замовчуванням плеєри беруть RTSP поверх UDP — найшвидший варіант.
  TCP-транспорт (проксі/VPN, що ріже UDP) додає head-of-line затримку
  при втратах.

Не використовуйте для десктопних плеєрів HTTP-адресу превʼю
(`/api/stream/preview`): вона йде по TCP як «файл, що дописується», і
кожен стал додає постійне відставання, яке плеєр сам не скидає. HTTP-лінк
лишається для браузерного плеєра сторінки — той доганяє живий край сам
(mpegts.js, latency chasing).

## 🔌 REST API і Swagger

Веб-сервіс віддає відкритий REST API на порту **8081** — без авторизації,
за IP-адресою (як і веб-інтерфейс). Масові операції флоту
(`/api/fleet/*`) додатково вимагають входу оператора.

- **Інтерактивний Swagger UI**: `http://<IP>:8081/api-docs/swagger`
  (або `/api/dzyga/ctl/docs`) — специфікація OpenAPI 3 у
  `/api/dzyga/ctl/openapi.json`. За замовчуванням показується лише
  публічний контракт; ендпоінти, які обслуговують вбудований веб-UI,
  доступні в повній специфікації `openapi.json?internal=1` з міткою
  `x-internal` (перемикач зверху сторінки Swagger UI).
- **Практичний гайд**: `http://<IP>:8081/api-docs` — рендериться з
  `web/templates/dzyga_api_docs.md`, єдиного джерела опису API
  (quickstart, приклади curl/Python, розбір SSE-екрана).
- CLI-приклад клієнта (у дереві вихідного коду):
  `python3 scripts/dzyga_api_client.py <IP> frequency 5800`.

Основні групи ендпоінтів: керування Дзигою (`/api/dzyga/ctl/*`), стрім
(`/api/stream/*`), конфіг (`/api/config*`), логи (`/api/logs*`), оновлення
(`/api/updates/*`, `/api/dzyga/*`, `/api/dzyga-web/*`, `/api/firmware/*`),
VPN (`/api/vpn/*`), мультивʼю й флот (`/api/multiview/*`, `/api/fleet/*`).
